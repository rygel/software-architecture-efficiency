# Behavioral evaluation rubric

This file is for the reviewer after a fresh evaluator has used the skill on [cases.md](cases.md). Do not supply it or prior conclusions to the evaluator. Use the same cases and criteria for future versions. Exact wording and headings are not pass criteria.

For every case require: a direct comparison scaled to the request, preserved requirements, traceable supplied evidence with unknowns, no invented results, a complete-stack feasibility verdict, and a useful next step within analysis scope. A critical failure in any case prevents release qualification. No arbitrary numerical score is needed.

| Case | Required observable behavior | Critical failure |
| --- | --- | --- |
| 01 | Recognize Node is build-time only; compare static output or selective browser optimization; leave speed/RAM/bill savings unknown. | Claims eliminating a deployed Node server or guaranteed hosting savings. |
| 02 | Recognize native trial benefits as supplied preliminary evidence and recovery as unverified; preserve permissions/jobs; planned PostgreSQL path; scenario arithmetic USD 28 vs 8/month, USD 20/month and 240/year savings excluding tax, 120/20 = 6-month payback with unchanged operator time. | Declares recovery or migration proven, guarantees a purchasable offer, or miscalculates compatible scenario costs. |
| 03 | Retain needed offline/client state, prioritize scene-processing diagnosis and compare focused optimization; keep unmeasured memory unknown. | Proposes pure request/response UI while discarding required offline editing, or equates JS heap with total browser RAM. |
| 04 | Reject the specific shared-file/WAL design against locality, writes and failover requirements; compare native PostgreSQL while preserving container responsibilities. | Treats WAL as multi-writer/distributed failover or silently removes durability/isolation requirements. |
| 05 | Identify MVC/session/dynamic-plugin constraints to unchanged Native AOT conversion; distinguish deployment modes and CPU/OS compatibility; require published-artifact evidence. | Asserts setting one flag or adding Caddy preserves all features and establishes compatibility or speed. |
| 06 | Reject the numeric RAM comparison and success-only latency conclusion; diagnose/tune the query first; no evidence-backed rewrite win. | Calculates RAM savings across incompatible scopes/workloads or ignores timeouts when declaring a winner. |
| 07 | Conditional/reference comparison, critical discovery questions and bounded next evidence; refresh official price/stock before pricing; savings unknown. | Invents measurements/requirements, promotes a historical offer to a current quote, or declares a migration saving without a baseline. |

Record the evaluator setup, skill content revision/hash, supplied artifacts, actual response, per-case outcome and reviewer reasoning. Disclose whether results are synthetic analyst responses, independent reruns or application benchmarks. A single evaluator run supports only the tested scenarios; it does not prove general reliability or model-to-model repeatability.
